The same sources drive the Studio's settings forms, node docs and expression builder, and `schemas/flow.schema.json`.

Examples and a walkthrough: [`deploy/examples/flows/`](../deploy/examples/flows/). Validate a flow offline with `bun run scripts/cli.ts validate <file>` in `apps/runtime`.

## Flows directory

Everything lives in `FLOWS_DIR`:

| Entry | Meaning |
| --- | --- |
| `<id>.yaml / .yml / .json` | One flow per file. Reloaded on change without a restart. |
| `model-shortcuts.yaml` | Engines (named `PROVIDERS` instances), model presets (model id + parameters) and shortcuts — single engine/model pairs or pools with a selection strategy. Referenced as `llm.shortcut`. A change reloads all flows. |
| `constants.yaml` | `constants: { name: value }` shared by all flows, read as `{{const.<name>}}` in variable values. No secrets. A change reloads all flows. |
| `prompts/` | Prompt files included with `#[[file:prompts/<name>.md]]` in a `systemPrompt` (node or override); includes may nest up to 5 levels. |
| `subflows/` | Sub-flow files merged into a flow via `metadata.$include.subflows`; the Studio writes their nodes back into them. |
| `*.example.yaml` | Documentation templates; never loaded. |
| `dispatch, access, canary, guardrails, experiments, mcp, tool-authz, compliance-policy, shadow (.yaml)` | Reserved configuration files of other subsystems, never loaded as flows. |

The smallest valid flow:

```yaml
id: my-flow
name: My Flow
nodes:
  - id: answer
    type: llm
edges: []
```

## Flow fields

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | non-empty string | yes | Unique flow id; also the model name clients request. |
| `name` | non-empty string | yes | Display name. |
| `description` | string | no | What the flow does; shown in the Studio and model listing. |
| `priority` | integer 0–100 | no | Queue priority 0–100 under a concurrency cap (default 50); higher runs first. |
| `variables` | object | no | Named values referenced as `{{vars.<name>}}` in nodes and edges; overridable per request. Values may reference other variables, constants, `FLOW_PUBLIC_*` env and calculations. |
| `pricing` | object | no | Prices per 1,000,000 prompt/completion tokens keyed by model; override the central prices of `model-shortcuts.yaml` for cost accounting. |
| `dataClasses` | list of one of `public`, `internal`, `confidential`, `personal`, `sensitive`, `financial`, `legal`, `health` | no | Data classes this flow processes; matched by the compliance policy's data rules. |
| `requiredScopes` | list of string 1–256 chars (≤ 100) | no | OAuth/OIDC scopes a caller needs to discover and run this flow; all are required. |
| `recovery` | object | no | Crash recovery of async runs: `retry` states whether re-running from the start is safe; `maxAttempts` (1–10) lowers the global ceiling. |
| `nodes` | list of object 1–100 | no | The steps; 1–100. In a flow file optional when `metadata.$include` merges them in from sub-flows. |
| `edges` | list of object (≤ 500) | no | Connections between nodes; 0–500. The run starts at the first node; a node without an outgoing edge ends it. In a flow file optional when `metadata.$include` merges them in. |
| `metadata` | object | no | Free-form. Known keys: `version` (appears as flow_version in debug traces, next to flow_digest, a hash of the executed definition, and subflow_versions), `ui` (Studio layout), `$include.subflows` (sub-flow files), `hidden` (true = omit from GET /v1/models; the flow stays loadable and dispatchable). |

Keys starting with `_` (`_comment`, `_comment_tools`, …) are annotations on flows, nodes, edges and overrides; the parser ignores them. Any other unknown key is an error in `schemas/flow.schema.json`, which editors can use to validate flow files as you type (it describes the file form, including `llm.shortcut` and flows whose nodes come from `metadata.$include`).

Fields every node can carry. Which of them a node type uses is listed with the type.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | non-empty string | yes | Unique within the flow; edges and other nodes refer to it. |
| `type` | non-empty string | yes | A built-in node type (see the node types below) or a registered plugin type. |
| `label` | string | no | Display name in the Studio and in traces. |
| `priority` | integer 0–100 | no | Queue priority 0–100 of `llm`/`classifier` nodes; a flow's effective priority is the maximum of its own and its nodes'. |
| `llm` | object | no | The model of this node. In a flow file usually `{ shortcut: <name> }` from `model-shortcuts.yaml`, expanded to provider/model/parameters when the flow loads. |
| `tools` | list of string ≤ 128 chars (≤ 50) | no | MCP tool refs the node may call: `server/tool`, or `server/*` for all tools of a server; max. 50. |
| `config` | object | no | Type-specific settings; see the node type's settings table. |
| `classifierSchema` | object | no | Required for `classifier` nodes. |
| `systemPrompt` | string ≤ 65536 chars | no | System prompt; may include prompt files (`#[[file:prompts/x.md]]`) and runtime placeholders (`{{context.*}}`, `{{now.*}}`, …). |
| `overrides` | list of object (≤ 20) | no | Up to 20 variants of llm/tools/systemPrompt; all `when…` conditions of an entry must match, the first matching entry wins. |
| `parallelNodes` | list of non-empty string or object (≤ 20) | no | Children of a `parallel` node: node ids, or `{ node, condition }` to run a child conditionally; max. 20. |

`classifierSchema`:

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `schema` | object | yes | JSON Schema of the structured classification the model must return. |
| `classKey` | non-empty string | yes | Schema field whose value becomes `classLabel` for routing. |

Entries of `overrides`:

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `whenClass` | non-empty string | no | Matches when `classLabel` equals this value. |
| `whenClaim` | string 1–1024 chars | no | Condition expression over the caller's token claims. |
| `whenParam` | string 1–1024 chars | no | Condition expression over the request parameters. |
| `whenPlan` | non-empty string | no | Matches the tenant plan. |
| `whenGroup` | non-empty string | no | Matches when the caller is in this group. |
| `whenLanguage` | non-empty string | no | Matches the request language. |
| `llm` | object | no | The model of this node. In a flow file usually `{ shortcut: <name> }` from `model-shortcuts.yaml`, expanded to provider/model/parameters when the flow loads. |
| `tools` | list of string ≤ 128 chars (≤ 50) | no | Replaces the node's tools. |
| `systemPrompt` | string ≤ 65536 chars | no | Replaces the node's system prompt. |

## The `llm` block

Either a shortcut or an explicit provider and model:

```yaml
llm: { shortcut: fast-pool }
llm: { provider: eu-openai, model: a-chat-model, parameters: { temperature: 0.2 } }
```

| Field | Type | Description |
| --- | --- | --- |
| `shortcut` | string | Name of a model shortcut from `model-shortcuts.yaml` (or a `{{vars.*}}` reference to one). Expanded when the flow loads into `provider`, `model` and the preset's `parameters` (node-level `parameters` win); a pool shortcut additionally attaches its candidates. Use it instead of `provider` + `model`. Example: `"fast-pool"`. |
| `provider` | string | A provider instance name from the `PROVIDERS` environment variable, a built-in protocol name, or a `{{vars.*}}` reference. Checked against the provider registry when the flow loads. Example: `"eu-openai"`. |
| `model` | string (1–256) | The model id passed to the provider. Example: `"a-chat-model"`. |
| `parameters` | object (max. 20 keys) | Generation parameters; see the table below. Unknown keys are passed through unchanged. |

`parameters`:

| Key | Type | Description |
| --- | --- | --- |
| `temperature` | number 0–2 | Sampling temperature. |
| `maxTokens` | integer 1–65536 | Output token budget. Too small a budget for a thinking model ends in an empty answer. |
| `contextLength` | integer | The model's context window in tokens. Overrides the capability registry; the engine uses it to truncate prompts deterministically before clamping the output budget. |
| `reasoningEffort` | string | Sent as `reasoning_effort` to OpenAI-compatible servers (e.g. `none` disables thinking in LM Studio). Example: `"none"`. |
| `chatTemplateKwargs` | object | Sent as `chat_template_kwargs` to OpenAI-compatible servers (vLLM, Ollama). Example: `{"enable_thinking":false}`. |
| `extraBody` | object | Fields merged verbatim into the request body of OpenAI-compatible servers, e.g. anti-repetition penalties (`repeat_penalty`, `frequency_penalty`, `presence_penalty`, `top_k`, `min_p`). Example: `{"repeat_penalty":1.15}`. |
| `visionInput` | boolean | Attests that a model unknown to the capability registry accepts images. Unknown models otherwise fail closed. |
| `providerOptions` | object | Provider-specific options handed to the AI SDK as `providerOptions` (e.g. Google image model settings). |

## Settings on every node

These `config` keys apply to every node type.

| Key | Type | Default | Description |
| --- | --- | --- | --- |
| `errorStrategy` | one of `fail-fast`, `continue`, `fallback` | `fail-fast` | What the engine does when this node throws. `fail-fast` aborts the run with the error. `continue` records the error and carries on with the next node (the run can still succeed). `fallback` runs `fallbackNodeId` instead; without a fallback node it behaves like `continue`. |
| `fallbackNodeId` | node id | — | Node executed when this node fails and `errorStrategy` is `fallback`. If the fallback node also fails, the run fails with both errors. |
| `requiresApproval` | list of tool ids | — | Tool refs or patterns (`server/tool`, `server/*`, bare name) that must be approved by a human before this node may call them. The call pauses, an approval request appears in Approvals / the client stream, and it is denied automatically when nobody answers in time (fail-closed). Applies to `llm` agent loops and `tool` nodes. Example: `["taiga/task_create","parking/*"]`. |
| `progress` | object | — | Opt-in, server-authored lifecycle lines streamed to the client while this node runs (instead of exposing model reasoning). Any node with a `progress` object switches progress reporting on for the whole flow. |
| `progress.start` | string | — | Shown when the node starts. Falls back to the node label / id. |
| `progress.complete` | string | — | Shown when the node finishes successfully. |
| `progress.error` | string | — | Shown when the node fails. |

| Type | Summary |
| --- | --- |
| [`llm`](#llm-llm) | Streaming model call, optionally with an agent tool loop over MCP tools. |

| [`parallel`](#parallel-parallel) | Fan-out to child nodes and/or data-driven RAG sources, then merge. |

Any other `type` resolves through the plugin node-handler registry.

### `llm` — LLM

Streaming model call, optionally with an agent tool loop over MCP tools.

Calls a language model with the conversation so far, the node's system prompt and any grounding context injected by earlier nodes (retrieval, parallel/RAG, memory). The answer streams to the client unless a later node produces the final answer.

With `tools`, the node runs an **agent loop**: the model may call MCP tools, sees their results and continues until it answers or the step budget (`maxToolSteps`) is used up. Tool results are budgeted to the model's context window (`toolResultBudget`) and can be grounded/cited.

The model comes from `llm` (a shortcut or provider/model); without `llm` the runtime's `DEFAULT_LLM` is used. A shortcut that resolves to a **pool** gives the node an ordered fallback/round-robin chain of models.

Structured output: with `config.outputSchema` the node returns a JSON object instead of prose (see below). Classification-style routing is usually better done with a `classifier` node.

**When to use**

- Answering the user (responder, synthesizer).
- Agentic work with tools: research, lookups, actions (with approval for consequential tools).
- Any free-text transformation step (summarise, rewrite, extract into prose).

**Node fields**

| Field | Use | Meaning for this type |
| --- | --- | --- |
| `llm` | recommended | Model to call. Omit to use DEFAULT_LLM. |
| `systemPrompt` | recommended | Instructions for this step. Supports `#[[file:prompts/x.md]]` includes and `{{vars.*}}` / `{{context.*}}` / `{{node.<id>.classification.*}}` placeholders. |
| `tools` | optional | MCP tool refs (`server/tool`, `server/*`) the agent loop may call. Empty = plain model call. |
| `overrides` | optional | Conditional per-request variants, applied in order — the FIRST matching entry wins and replaces `llm`, `systemPrompt` and `tools` wholesale (keys it omits stay as on the node). Match conditions (all present ones must hold): `whenClass` (classLabel, `*` wildcard), `whenClaim` (expression over JWT claims, e.g. `role == 'admin'`), `whenParam` (expression over requestParams), `whenPlan` (exact), `whenGroup` (ctx.groups contains), `whenLanguage` (BCP-47 prefix, `de` matches `de-AT`). Example: `[{ whenClass: "SIMPLE", llm: { shortcut: fast }, systemPrompt: "..." }]`. |
| `priority` | optional | Queue priority for model requests from this node; higher runs first. A flow's effective priority is the maximum of its own and those of its `llm`/`classifier` nodes. |
| `classifierSchema` | ignored | Not used — that is the `classifier` type. For a schema-constrained answer from an `llm` node use `config.finalAnswerContract` or a structured downstream classifier. |
| `label` | optional | Human-readable name shown on the canvas, in lists and as the default progress text. Purely cosmetic — edges, templates and references address the node by its `id`. |

**Settings (`config`)**

| Key | Type | Default | Description |
| --- | --- | --- | --- |
| `maxToolSteps` | integer ≥ 1 | runtime MAX_TOOL_STEPS | Upper bound on model↔tool round trips in one turn. Raise it for agentic nodes that read many documents; invalid values fall back to the global setting. |
| `toolArgs` | json | — | Per tool ref, arguments fixed server-side: `{ "server/tool": { arg: value } }`. On `llm` nodes they are MERGED over what the model supplies (the model still chooses e.g. `query`, the configured keys are enforced); on `tool` nodes they are the complete argument set. String values may contain templates resolved against the run state: `{{query}}`, `{{classification.<field>}}`, `{{node.<id>.classification.<field>}}`, `{{turn[1].<id>.classification.<field>}}`, `{{context.<key>}}`. Use it to pin e.g. a vectorsearch `collection` so a model can't hit the wrong store. Example: `{"vectorsearch/search":{"collection":"cases","tags":["{{classification.clientTags}}"]}}`. |
| `toolSelection` | object | — | With many tools, advertise only the relevant ones. In `semantic` mode the node's full `tools` list becomes a candidate pool: all stay callable, but only `alwaysInclude` + the top-K semantic matches (+ an optional `select_tools` meta-tool the model can use to pull more in) are advertised initially. |
| `toolSelection.mode` | one of `static`, `semantic` | `static` | `static` advertises every tool; `semantic` gates by embedding similarity to the request. |
| `toolSelection.topK` | integer ≥ 1 | `5` | Max semantically selected tools advertised initially. |
| `toolSelection.minScore` | number 0–1 | — | Drop semantic hits below this cosine similarity. |
| `toolSelection.alwaysInclude` | list of tool ids | — | Refs/patterns always advertised (full ref, bare name, `server/*`, `*`). |
| `toolSelection.metaTool` | boolean | — | Expose the on-demand `select_tools` meta-tool. |
| `toolSelection.metaToolName` | string | `select_tools` | Name advertised for the meta-tool. |
| `toolSelection.metaTopK` | integer ≥ 1 | `2` | Max tools activated per meta-tool call. |
| `toolSelection.cacheStable` | boolean | `false` | Advertise the full pool in a stable order instead of gating per request — keeps the tools+system prompt prefix byte-identical so provider prompt caching hits. Good for hot multi-turn nodes with a large stable prompt. |
| `requireToolUse` | boolean | `false` | A contract: a text-only answer is worthless, so the node must call at least one tool before it may answer. If the model keeps refusing, the node FAILS rather than emitting ungrounded prose. Use for researcher nodes whose findings must come from real retrieval. |
| `requireToolUseWhenSelected` | boolean | `false` | A heuristic: force a tool call only when semantic tool selection found a plausibly relevant tool. Unlike `requireToolUse` it never fails the turn — when the forced call is refused the user still gets an answer. Messages without own intent ("retry", "test", "ok"…) never trigger it. |
| `requireToolUseWhenSelectedMinScore` | number 0–1 | — | Minimum semantic score the best-selected tool needs before `requireToolUseWhenSelected` forces a call. |
| `toolSequenceContract` | json | — | For consequential actions: when the user message matches `when.pattern` (a regex, optional `when.flags`), the tools in `sequence` must all have succeeded in that order before the answer is accepted. Invalid declarations are ignored. Example: `{"when":{"pattern":"buche\|reservier","flags":"i"},"sequence":["parking/availability","parking/book_space"]}`. |
| `toolLoopGuard` | object | disabled (enable with `true` for defaults) | Opt-in guard against a model stuck in a tool-call loop. `true` enables it with defaults; an object tunes the detectors. Counts identical calls, same-tool churn (varying args, time-windowed), mutating calls with no observable effect, and A→B→A→B cycles — each with a warn threshold (a steering notice is injected) and a block threshold (the repeated call is refused). Failed tool outcomes count toward churn so a retry storm is caught; policy/approval waits pause the clock. |
| `toolLoopGuard.enabled` | boolean | `true` | Master switch — only relevant when the object form is used; `toolLoopGuard: true` enables with defaults. |
| `toolLoopGuard.identicalWarnAt` | integer ≥ 2 | `3` | Identical calls (same tool, same args) before a warning is injected. |
| `toolLoopGuard.identicalBlockAt` | integer ≥ 2 | `5` | Identical calls before the repeat is blocked. |
| `toolLoopGuard.churnWarnAt` | integer ≥ 2 | `6` | Same-tool calls with varying args inside the window before a warning. |
| `toolLoopGuard.churnBlockAt` | integer ≥ 2 | `10` | Same-tool calls with varying args inside the window before blocking. |
| `toolLoopGuard.churnWindowMs` | integer ≥ 1000 | `120000` | Time window in which churn is counted; paused time (approvals) is excluded. |
| `toolLoopGuard.noProgressWarnAt` | integer ≥ 2 | `3` | Mutating calls with no observable effect before a warning. |
| `toolLoopGuard.noProgressBlockAt` | integer ≥ 2 | `5` | Mutating calls with no observable effect before blocking. |
| `toolLoopGuard.cycleWarnAt` | integer ≥ 2 | `3` | A→B→A→B cycle repetitions before a warning. |
| `toolLoopGuard.cycleBlockAt` | integer ≥ 2 | `4` | A→B→A→B cycle repetitions before blocking. |
| `clientTools` | boolean | `true` | Whether tools sent by the caller (OpenAI `tools` in the request, e.g. Open WebUI knowledge/functions) are offered to this node when client tools are enabled globally. Set false for RAG-only nodes that must answer strictly from the flow's own tools. |
| `suppressToolPreamble` | boolean | `false` | Buffer any text the model writes before a tool call until it is known whether a tool follows. If one does, the narration ("I will now search…") is discarded; if not, it is emitted as the answer. Keeps internal plans out of the client. |
| `streamToolResultDetails` | boolean | `true` | When false, tool calls stay visible in the client stream (name, status, duration) but their result payload is not streamed. The result still feeds grounding, citations, monitoring and the next model call. Use for private worker nodes. |
| `toolResultBudget` | object | — | Caps on tool output fed back to the model. Derived from the model's context window by default (fixed defaults when the window is unknown); set to override. |
| `toolResultBudget.perResultChars` | integer 1000–1000000 | — | Max characters kept from one tool result. |
| `toolResultBudget.perTurnChars` | integer 1000–2000000 | — | Max tool-result characters across one turn. |
| `toolContext` | json | — | Retrieves evidence with a context tool before (`pre`) and/or after (`post`) matching tool calls and attaches it to the call — e.g. look up the case file before creating a ticket. `server`/`tool` default to `vectorsearch`/`retrieve_evidence`. Each stage: `match` (tool patterns, default `["*"]`), `queryTemplate` (required), `arguments`, `handleArgument`, `required` (fail the action when no evidence, default false), `appendEvidence` (default true), `maxResultChars` (default 8000, min 256). `evidenceContract: { match, required }` declares actions that must carry a verified evidence pack into governance. Example: `{"server":"vectorsearch","tool":"retrieve_evidence","pre":{"match":["taiga/task_create"],"queryTemplate":"{{query}}","required":true}}`. |
| `refHandles` | boolean | `false` | Replace long document references in tool results with short 4-character handles (e.g. `K3NQ`) that the model reads and quotes; the runtime maps them back to the real references before the tool call and in everything the user sees. Use on tool-loop nodes whose model must re-quote `reference`/`base_ref` arguments — small models truncate long paths. Unknown handles are rejected with the valid list instead of hitting the backend. Path-shaped references that no tool returned in this run are rejected the same way (`unregistered_ref`); `link` is never a reference. |
| `turnContext` | string (multi-line) | — | Per-request context appended to the newest user turn (not the system prompt). Supports {{context.*}}, {{now.*}}, {{node.<id>.classification.<field>}} and {{turn[n]...}}. Omitted when every referenced placeholder resolves empty. Use for classifier output such as an image transcription. |
| `sourcesCheck` | object | — | Opt-in deterministic check of the final answer (every switch defaults to off). `completeSection` appends each inline-cited `[n]` that the sources section lacks, built only from the sources registered in this execution, as a trailing stream chunk; it creates the section when missing. Unregistered `[n]` are reported, never invented. `stripRuleMarkers` removes the pseudo marker `[Regel: …]` from answer text that has not been streamed yet (buffered answers, e.g. with `suppressToolPreamble`). Results are reported in the `answer_sources_check` diagnostic. |
| `sourcesCheck.completeSection` | boolean | `false` | Append inline-cited `[n]` missing from the sources section, from registered sources only. |
| `sourcesCheck.heading` | string (multi-line) | — | Markdown heading of the sources section, matched by its text (default `## Quellen`). |
| `sourcesCheck.stripRuleMarkers` | boolean | `false` | Remove the pseudo marker `[Regel: …]` from not-yet-streamed answer text. Other bracketed content is left untouched. |
| `outputSchema` | json | — | Makes the node return a JSON object instead of prose: `{ name?: string (default "output"), schema: <JSON Schema> }`. Uses native structured output where the model supports it, otherwise a schema hint + tolerant parse. A malformed schema is treated as not configured (the node streams normally). Cannot be combined with `finalAnswerContract`. Example: `{"name":"result","schema":{"type":"object","properties":{"status":{"type":"string"}},"required":["status"]}}`. |
| `finalAnswerContract` | object | — | Only the text between two markers is the answer; everything else (plans, scratch work) is dropped. The output is buffered and validated (both markers present once, in order, non-empty, not a placeholder like `...`). Cannot be combined with `outputSchema`. |
| `finalAnswerContract.startMarker` (required) | string | — | Exact marker the model writes before the final answer. |
| `finalAnswerContract.endMarker` (required) | string | — | Exact marker after the final answer. |
| `finalAnswerContract.streamAfterStartMarker` | boolean | `false` | Start streaming once the start marker appeared (marker text itself never reaches the client) instead of buffering the whole answer. |
| `maxOutputChars` | integer 1000–1000000 | runtime LLM_MAX_OUTPUT_CHARS, else 64000 | Hard ceiling on generated characters (answer and reasoning together); generation is cut off there. Protects against runaway or looping generations. |
| `emptyResponseFallback` | boolean | `false` | When every attempt and every fallback model returned an empty completion, emit a short neutral answer instead of failing the node. Use on worker nodes inside an agent harness so one empty turn doesn't abort the whole run. |
| `emptyResponseFallbackText` | string | (No answer was produced for this step.) | The text emitted by `emptyResponseFallback`. |
| `reasoningSalvage` | boolean | true (unless the runtime fallback policy is `explicit`/`disabled`) | When a reasoning model puts its whole answer into the reasoning channel and returns empty visible text, use the reasoning as the answer. Set false where reasoning must never be shown. |
| `allowToolUseFallback` | boolean | true (unless the runtime fallback policy is `explicit`/`disabled`) | Allow the runtime to recover a tool call the model described in text instead of emitting it natively. |
| `dropRagContext` | boolean | `false` | Remove injected RAG / collection-overview system messages from this node's prompt. For synthesizers that work only from carried-forward findings (which already contain the [n] citations). Citations stay registered. |
| `maxHistoryTurns` | integer ≥ 1 | — | Keep only the last N conversation turns in this node's prompt. Absent = full history. |
| `historyCompression` | object | — | Summarises older turns when the context gets full. Identical tool results are always deduplicated; summarisation engages above the threshold and needs a known context window. The summary is cached per conversation+node so the prompt prefix stays stable. |
| `historyCompression.enabled` | boolean | `false` | Turns history summarisation on; without it only duplicate tool results are removed. |
| `historyCompression.thresholdRatio` | number 0–1 | — | Share of the context window above which summarisation starts. |
| `historyCompression.llm` | model (`llm` block) | — | Model used for summaries; defaults to this node's model. A model: `{ shortcut: <name from flows/model-shortcuts.yaml> }` or `{ provider, model, parameters? }` (provider = a PROVIDERS name or protocol). |
| `allowTrailingAssistantTurn` | boolean | `false` | Normally a user turn is appended when the prompt would end on an assistant message (local Qwen builds answer that with an immediate end token, i.e. an empty completion). Set true only for a node that should continue its own last message. |
| `inputFilter` | one of `attachments`, `current-turn-attachments` | — | Skip this node unless the conversation (`attachments`) or the latest user message (`current-turn-attachments`) contains attachments. For vision/extraction steps. |
| `imageInspection` | object | — | Keeps a text-only node usable with images: inline images are parked as `img-N` references and the node gets a tool to ask a vision model about them. The vision model is mandatory (it must support vision input). |
| `imageInspection.llm` (required) | model (`llm` block) | — | Model that looks at the images. A model: `{ shortcut: <name from flows/model-shortcuts.yaml> }` or `{ provider, model, parameters? }` (provider = a PROVIDERS name or protocol). |
| `imageInspection.description` | string (multi-line) | — | Description of the inspection tool shown to the hosting model (max 2000 chars). |
| `imageInspection.imageDescription` | string | — | Description of the image argument (max 1000 chars). |
| `imageInspection.maxAnswerChars` | integer 200–100000 | — | Cap on the vision answer injected into the context. |
| `imageInspection.assetSource` | json | — | Enables `asset:<id>[#bbox]` references, fetched via the MCP `get_asset` tool. Object with `server` (required, the MCP server exposing get_asset), optional `collection`, and optional `variant` (thumb\|preview\|full). |
| `mediaTools` | json | — | Tools that generate images/audio/video with their own model and stream the result straight to the user: an array of `{ name, llm, description?, promptDescription? }`. The hosting model only passes a `prompt`. Example: `[{"name":"generate_image","llm":{"shortcut":"gemini-image"},"description":"Erzeugt ein Bild zur Beschreibung"}]`. |
| `routing` | json | — | Picks the model per request from `candidates` (LlmConfig list): `strategy` `cheapest` (blended cost/token), `balanced` (cost for this prompt size) or `quality-aware` (cheapest with observed quality ≥ `minQualityScore`, default 0.7; fewer than `minQualitySamples`, default 5, observations = exploration). Also what the Studio's Optimize panel analyses. Example: `{"strategy":"quality-aware","candidates":[{"shortcut":"fast-pool"},{"shortcut":"sonnet"}],"minQualityScore":0.8}`. |
| `objective` | json | — | Generalised routing (takes precedence over `routing`): `candidates` (LlmConfig list) walked cheapest-first, the first one meeting ALL `objectives` (`{ metric: "quality"\|"cost", op: "gte"\|"lte", value }`) wins. `minQualitySamples` (default 5; fewer = unproven, treated as eligible), `maxAttempts`, `fallback` (`cheapest` \| `best-quality` \| `first`). Every attempt is recorded in the explainability card. Example: `{"candidates":[{"shortcut":"fast-pool"},{"shortcut":"sonnet"}],"objectives":[{"metric":"quality","op":"gte","value":0.8}],"fallback":"best-quality"}`. |

**Example: Responder with a model shortcut**

```yaml
- id: answer
  type: llm
  label: Antwort
  llm:
    shortcut: "{{vars.model_responder}}"
    parameters: { temperature: 0.2, maxTokens: 4096 }
  systemPrompt: "#[[file:prompts/answer.md]]"
```

**Example: Researcher with pinned vectorsearch collection**

```yaml
- id: research
  type: llm
  llm: { shortcut: fast-pool }
  tools: [vectorsearch/search, vectorsearch/get_documents]
  config:
    maxToolSteps: 14
    requireToolUse: true
    suppressToolPreamble: true
    toolArgs:
      vectorsearch/search: { collection: cases }
      vectorsearch/get_documents: { collection: cases }
```

**Notes**

- Unknown config keys are kept and ignored by the runtime — a typo silently does nothing. The Studio lists them under “Other keys”.
- Tool refs of MCP servers the runtime isn't connected to only produce a warning; the node works where the server is available.

### `tool` — Tool

Deterministic MCP tool calls — no model involved.

Calls every tool in `tools` with fixed arguments from `config.toolArgs` (templates resolved against the run state) and accumulates the results. No LLM decides anything — use it for lookups whose parameters are known, e.g. from a classifier.

Search-style results (vectorsearch) become grounding context and citations for the next LLM node; other results are only visible downstream when `injectResultContext` is set.

**When to use**

- Fetch data with parameters taken from a classification (ticket id, client, date).
- Page through a complete listing (`paginate`) to build an overview.

**Node fields**

| Field | Use | Meaning for this type |
| --- | --- | --- |
| `tools` | required | Tool refs to call, in order. |
| `overrides` | optional | Conditional per-request variants of `tools` — the only way to vary which tools this node calls. Entries match on `whenClass`/`whenClaim`/`whenParam`/`whenPlan`/`whenGroup`/`whenLanguage`, first match wins. The `llm`/`systemPrompt` of a matching entry are resolved but unused, like the node-level ones. |
| `llm` | ignored | Not used — no model is involved. |
| `systemPrompt` | ignored | Not used — no model is involved. |
| `label` | optional | Human-readable name shown on the canvas, in lists and as the default progress text. Purely cosmetic — edges, templates and references address the node by its `id`. |

**Settings (`config`)**

| Key | Type | Default | Description |
| --- | --- | --- | --- |
| `toolArgs` | json | — | Per tool ref, arguments fixed server-side: `{ "server/tool": { arg: value } }`. On `llm` nodes they are MERGED over what the model supplies (the model still chooses e.g. `query`, the configured keys are enforced); on `tool` nodes they are the complete argument set. String values may contain templates resolved against the run state: `{{query}}`, `{{classification.<field>}}`, `{{node.<id>.classification.<field>}}`, `{{turn[1].<id>.classification.<field>}}`, `{{context.<key>}}`. Use it to pin e.g. a vectorsearch `collection` so a model can't hit the wrong store. Example: `{"vectorsearch/search":{"collection":"cases","tags":["{{classification.clientTags}}"]}}`. |
| `args` | json | — | Arguments applied to EVERY tool this node calls; `toolArgs[ref]` overrides them per tool. String values may contain templates (`{{query}}`, `{{classification.<field>}}`, …) resolved against the run state. Use it when several tools share the same parameter instead of repeating it in each `toolArgs` entry. Example: `{"format":"json","limit":50}`. |
| `paginate` | json | — | Per tool ref: call it repeatedly with an increasing offset until the server-reported `total` is fetched or `maxPages` (default 50) is hit. `{ "server/tool": { offsetParam?: "offset", limitParam?: "limit", maxPages?: 50 } }`; page size defaults to 200. Example: `{"vectorsearch/list_documents":{"offsetParam":"offset","limitParam":"limit","maxPages":20}}`. |
| `overviewCharBudget` | integer | — | Raise the character budget of the injected collection overview so large dossiers list all document titles, not just the leading subset. |
| `streamToolResultDetails` | boolean | `true` | When false, tool calls stay visible in the client stream (name, status, duration) but their result payload is not streamed. The result still feeds grounding, citations, monitoring and the next model call. Use for private worker nodes. |
| `injectResultContext` | boolean | `false` | Pass non-search tool results (and errors) to the next LLM node as one system message. Without it only search results become context. |
| `maxResultContextChars` | integer 1000–100000 | `20000` | Size cap for the injected result message. |
| `toolContext` | json | — | Retrieves evidence with a context tool before (`pre`) and/or after (`post`) matching tool calls and attaches it to the call — e.g. look up the case file before creating a ticket. `server`/`tool` default to `vectorsearch`/`retrieve_evidence`. Each stage: `match` (tool patterns, default `["*"]`), `queryTemplate` (required), `arguments`, `handleArgument`, `required` (fail the action when no evidence, default false), `appendEvidence` (default true), `maxResultChars` (default 8000, min 256). `evidenceContract: { match, required }` declares actions that must carry a verified evidence pack into governance. Example: `{"server":"vectorsearch","tool":"retrieve_evidence","pre":{"match":["taiga/task_create"],"queryTemplate":"{{query}}","required":true}}`. |

**Example: Read a ticket by the id a transform extracted**

```yaml
- id: taiga-ticket-live
  type: tool
  tools: [taiga/userstory_detail]
  config:
    toolArgs:
      taiga/userstory_detail: { ref: "{{classification.ticketId}}" }
    injectResultContext: true
```

**Notes**

- An unresolved template becomes an empty string, never the literal `{{…}}`.

### `router` — Router

Routing only — evaluates the conditions on its outgoing edges.

Does no work itself. After it runs, its outgoing edges are evaluated: the first edge whose `conditions` expression is true is taken; an edge without condition is the default.

Expressions can read `classLabel`, `classification.<field>`, `node.<id>.classification.<field>` (this run), `turn[<n>].<id>.classification.<field>` (earlier turns), `messageCount`, `hasErrors`, `errorCount`, `toolResultCount`, `lastMessageText`, `currentNodeId`. Operators: `== != === !== < <= > >= && || !`, `+ -`, parentheses, and `=~` (case-insensitive regex test, e.g. `lastMessageText =~ 'parkplatz|stellplatz'`). Methods: `.includes(x)` / `.contains(x)`, `.startsWith(x)`, `.endsWith(x)`, `.length`; array index `x[0]`. Literals: numbers, 'strings', true/false, null. No code execution — anything else is a validation error.

**When to use**

- Branch after a classifier.
- Merge point that fans out to several alternatives.

**Node fields**

| Field | Use | Meaning for this type |
| --- | --- | --- |
| `llm` | ignored | Not used — routing is deterministic, no model runs. |
| `systemPrompt` | ignored | Not used — no model runs. The routing logic lives in the edges' `conditions`. |
| `tools` | ignored | Not used — MCP tools are called by `llm` and `tool` nodes. Route to one of those when this step needs a tool. |
| `label` | optional | Human-readable name shown on the canvas, in lists and as the default progress text. Purely cosmetic — edges, templates and references address the node by its `id`. |

**Settings (`config`)**

No type-specific settings.

**Example: Route by a classification field**

```yaml
edges:
  - { source: router, target: retoure, conditions: "classification.route == 'RETOURE'" }
  - { source: router, target: answer-fast }   # default
```

**Notes**

- Hyphenated node ids can't be referenced in edge expressions (they work in templates). Use ids with underscores for classifiers you route on.

### `classifier` — Classifier

Structured output that sets `classification` (and `classLabel`) for routing.

Asks the model for an object matching `classifierSchema.schema` and stores it as `state.classification`; the field named by `classifierSchema.classKey` also becomes `classLabel`. Edge conditions, templates (`{{classification.x}}`) and later nodes read it.

Uses native structured output where the model supports it, otherwise a schema hint and tolerant JSON parsing. With a model pool, an unparseable answer rotates to the next model; when nothing parses, `config.fallback` is used instead of failing the turn.

**When to use**

- Triage/intent detection before a router.
- Extracting routing-relevant fields (client, needsInfo, hasAttachment).

**Node fields**

| Field | Use | Meaning for this type |
| --- | --- | --- |
| `classifierSchema` | required | `{ classKey, schema }` — JSON Schema of the result; `classKey` names the label field. |
| `llm` | recommended | Model; a pool gives per-model fallback. |
| `systemPrompt` | recommended | Classification instructions; may reference earlier classifiers via `{{node.<id>.classification.*}}`. |
| `priority` | optional | Queue priority for model requests from this node; a flow's effective priority is the maximum of its own and those of its `llm`/`classifier` nodes. |
| `tools` | ignored | Not used — a classifier makes one structured call and never enters a tool loop. Classify first, then let an `llm` or `tool` node act on the result. |
| `overrides` | ignored | NOT applied: unlike `llm` and `tool` nodes, a classifier reads `llm`/`systemPrompt` directly and never consults `overrides`. Put the variation in the prompt or split the node. |
| `label` | optional | Human-readable name shown on the canvas, in lists and as the default progress text. Purely cosmetic — edges, templates and references address the node by its `id`. |

**Settings (`config`)**

| Key | Type | Default | Description |
| --- | --- | --- | --- |
| `responseFormat` | one of `json`, `xml` | `json` | Output format asked of the model. `xml` helps models that struggle with JSON. |
| `fallback` | json | — | Classification used when no model produced parseable output, so the turn continues on a safe route instead of failing. Example: `{"route":"ALLGEMEINES","needsInfo":false}`. |
| `inputFilter` | one of `attachments`, `current-turn-attachments` | — | Skip this node unless the conversation (`attachments`) or the latest user message (`current-turn-attachments`) contains attachments — for vision-preprocessing classifiers that would otherwise burn a model call on every text-only turn to answer "no image". The skip resolves to `config.fallback` (required — without it the filter is ignored with a trace warning), records the node as completed with a `classifier_skipped_no_attachments` diagnostic, and makes no model call. |

**Example: Triage**

```yaml
- id: triage
  type: classifier
  llm: { shortcut: structured-pool }
  classifierSchema:
    classKey: route
    schema:
      type: object
      properties:
        route: { type: string, enum: [RETOURE, TENANTS, BETRIEB, ALLGEMEINES] }
        needsInfo: { type: boolean }
      required: [route, needsInfo]
  config:
    fallback: { route: ALLGEMEINES, needsInfo: false }
```

### `parallel` — Parallel

Fan-out to child nodes and/or data-driven RAG sources, then merge.

Runs the nodes listed in `parallelNodes` concurrently (each entry a node id or `{ node, condition }` — the child only runs when the condition is true) and merges their messages/results.

With `config.ragProfiles` it also acts as a **context assembler**: a retrieval plan per request profile, compiled at runtime into `vectorsearch/search` calls. Results of all sources are fused (reranker or score-only), deduplicated per document and injected as grounding context with citations.

**When to use**

- Assemble context from several collections at once.
- Run independent enrichment steps (memory recall, vision extraction) side by side.

**Node fields**

| Field | Use | Meaning for this type |
| --- | --- | --- |
| `parallelNodes` | recommended | Child node ids, or `{ node, condition }` for conditional children. Without it the node only runs `config.ragProfiles`. |
| `llm` | ignored | Not used — the children carry their own models. The RAG compression model is `config.ragCompression.llm`. |
| `systemPrompt` | ignored | Not used — the children carry their own prompts. |
| `tools` | ignored | Not used — `config.ragProfiles` is compiled into the search calls, and children call their own tools. |
| `label` | optional | Human-readable name shown on the canvas, in lists and as the default progress text. Purely cosmetic — edges, templates and references address the node by its `id`. |

**Settings (`config`)**

| Key | Type | Default | Description |
| --- | --- | --- | --- |
| `ragProfiles` | json | — | `profiles`: name → list of sources; `select`: `[{ when: <condition>, use: <profile> }]` (first match wins), else `default`; `shared`: sources added to every profile. A source: `{ collection (required), tags?, limit? (≤100), hybrid?, minScore? (0–1), scoreWeight?, when?, rerank? (default true), groupByDocument? (default true), includeAllVersions?, validAt? (RFC 3339), filter?, filterV2?, pathPrefix?, hyde?, expand?, granularity?, includeAssets?, assets? }` — `tags` may be `{{…}}` templates. `filter` (metadata equality), `filterV2` (eq/in/range operators), `pathPrefix` (folder scope) and `hyde` (HyDE query expansion) are forwarded to vectorsearch. v2 retrieval: `expand` (none\|neighbors\|section\|page) pulls in surrounding context, `granularity` (chunk\|section\|page\|document) picks the unit size, `includeAssets` (none\|refs\|thumbnails, sent as `include_assets`) returns figure assets per hit; omitted → pre-v2 behaviour. `assets: { attach? (none\|auto\|always, default none), maxImages? (1–20, default 4), variant? (thumb\|preview\|full, default preview) }` attaches hit figures as image parts to the responder message — `auto` only when `config.responderLlm` confirms vision input, `always` regardless; the first source declaring `assets` sets the policy for the node. Fusion: `rerank: { topN }` (model rerank) or `maxDocuments` (score-only), plus `minScore`. Example: `{"select":[{"when":"classification.route == 'RETOURE'","use":"retoure"}],"default":"allgemein","profiles":{"retoure":[{"collection":"retoure-docs","tags":["{{classification.clientTag}}"],"limit":8}],"allgemein":[{"collection":"docs","limit":6}]},"maxDocuments":8}`. |
| `ragCompression` | object | — | After fusion, a small model condenses each source to the parts relevant to the question and drops irrelevant ones. Fail-open: on any problem the original chunks are used. |
| `ragCompression.enabled` (required) | boolean | — | Turns the compression pass on; without it the fused chunks are used as retrieved. |
| `ragCompression.llm` (required) | model (`llm` block) | — | Small extraction model. A model: `{ shortcut: <name from flows/model-shortcuts.yaml> }` or `{ provider, model, parameters? }` (provider = a PROVIDERS name or protocol). |
| `ragCompression.minChars` | integer ≥ 0 | `400` | Only compress chunks at least this long. |
| `ragCompression.maxTokens` | integer ≥ 1 | `2048` | Output budget of the extraction call. |
| `followupDownweight` | object | — | In threaded conversations, documents already shown in earlier turns compete at a reduced weight so follow-ups prefer fresh material (they can still resurface when strongly relevant). No effect on the model-rerank path. |
| `followupDownweight.enabled` | boolean | — | Turns down-weighting on (only effective in threaded conversations). |
| `followupDownweight.factor` | number 0–1 | `0.5` | Weight multiplier for already-seen documents. |
| `followupDownweight.cap` | integer ≥ 1 | `100` | How many seen documents are remembered across turns. |
| `maxFanoutConcurrency` | integer ≥ 0 | `0` | Limit how many children run at the same time (0 = all at once). Protects provider rate limits and single local inference servers. |

**Example: Context assembler with a conditional vision child**

```yaml
- id: rag-context
  type: parallel
  parallelNodes:
    - recall
    - { node: vision-extract, condition: "classification.hasAttachment == true" }
  config:
    ragProfiles:
      default: allgemein
      profiles:
        allgemein: [{ collection: docs, limit: 6 }]
```

**Notes**

- Children referenced only via `parallelNodes` need no edges; the Studio draws them as dashed reference links.

### `retrieval` — Retrieval

RAG: embeds the query and injects the top-K chunks of one collection.

Embeds the latest user message, fetches the most similar chunks from `config.collection` in the platform vector store and injects them as grounding context and citations for the next LLM node. Requires RAG to be configured (vector store + embedding model); without a collection or RAG the node is a no-op and the flow runs ungrounded. For vectorsearch collections and multi-source plans use a `parallel` node with `ragProfiles` or a `tool` node instead.

**When to use**

- Simple single-collection grounding on the built-in vector store.

**Node fields**

| Field | Use | Meaning for this type |
| --- | --- | --- |
| `llm` | ignored | Not used. The embedding model is a deployment setting (`EMBEDDING_MODEL`), not a node field — this node cannot be pointed at a different one. |
| `systemPrompt` | ignored | Not used — no model is prompted here. The retrieved chunks are injected for the NEXT llm node, whose prompt applies. |
| `tools` | ignored | Not used — this node queries the platform vector store directly. For vectorsearch MCP collections use a `tool` or `parallel` node. |
| `label` | optional | Human-readable name shown on the canvas, in lists and as the default progress text. Purely cosmetic — edges, templates and references address the node by its `id`. |

**Settings (`config`)**

| Key | Type | Default | Description |
| --- | --- | --- | --- |
| `collection` (required) | string | — | Vector collection to search. Without it the node does nothing. |
| `topK` | integer ≥ 1 | `4` | Number of chunks to inject. |
| `minScore` | number 0–1 | — | Drop chunks below this cosine similarity. |

**Example: Docs retrieval**

```yaml
- id: retrieve
  type: retrieval
  config: { collection: docs, topK: 6, minScore: 0.3 }
```

### `memory` — Memory

Recalls long-term memories of the user/tenant for personalisation.

Recalls the memories most relevant to the request for the caller's scope and injects them as a system message for the next LLM. Memories are personalisation, not sources: they are not cited and don't affect the groundedness gate. No-op when memory is disabled or the request is anonymous.

**When to use**

- Personal assistants and support flows that should remember user facts.

**Node fields**

| Field | Use | Meaning for this type |
| --- | --- | --- |
| `llm` | ignored | Not used. Recall runs against the memory store with the deployment's embedding model, not a per-node one. |
| `systemPrompt` | ignored | Not used — no model is prompted. The recalled memories become a system message for the next llm node. |
| `tools` | ignored | Not used — MCP tools are called by `llm` and `tool` nodes. Route to one of those when this step needs a tool. |
| `label` | optional | Human-readable name shown on the canvas, in lists and as the default progress text. Purely cosmetic — edges, templates and references address the node by its `id`. |

**Settings (`config`)**

| Key | Type | Default | Description |
| --- | --- | --- | --- |
| `topK` | integer ≥ 1 | MEMORY_TOP_K, else 5 | Number of memories to recall. |
| `minScore` | number 0–1 | — | Minimum similarity for a memory to be included. |

### `agent-harness` — Agent harness

Planner/worker loop that delegates tasks to other nodes within budgets.

An orchestrator: a planner model splits the request into tasks and delegates each to a node from `allowlist` (the delegated nodes run like normal nodes). After each round it re-plans with the findings until done, a stop signal appears, or a budget (iterations, cost, time) is exhausted.

Optional **verification** delegates the findings to a reviewer node that must answer with the pass signal before the run counts as complete. **Plannerless** mode skips the planner and loops a worker (optionally over a deterministic document coverage queue).

Results either stay the delegated answers (`resultMode: delegated`, harness is the end node) or are aggregated into one context message for a downstream synthesizer (`context`).

**When to use**

- Multi-step, multi-domain questions.
- Exhaustive research over a corpus (coverage queue).

**Node fields**

| Field | Use | Meaning for this type |
| --- | --- | --- |
| `llm` | optional | Default planner model (overridden by `config.plannerLlm`). |
| `systemPrompt` | optional | Domain guidance for the PLANNER, prepended to the generic planning instructions — not a prompt for the delegated nodes (those carry their own). Ignored entirely when `config.plannerless` is true, because no planner runs. |
| `tools` | ignored | Not used — the harness calls no tools itself, it delegates to the `config.allowlist` nodes, which carry their own tools. |
| `overrides` | ignored | NOT applied: only `llm` and `tool` nodes consult `overrides`. |
| `label` | optional | Human-readable name shown on the canvas, in lists and as the default progress text. Purely cosmetic — edges, templates and references address the node by its `id`. |

**Settings (`config`)**

| Key | Type | Default | Description |
| --- | --- | --- | --- |
| `allowlist` (required) | list of node ids | — | Node ids the harness may delegate to (at least one). The Studio draws them as dotted links when the harness is selected. |
| `maxIterations` | integer 1–1000 | `12` | Hard cap on plan/delegate rounds. |
| `maxCost` | number ≥ 0 | — | Stop when the accumulated cost reaches this. |
| `maxTimeMs` | integer ≥ 1 | — | Wall-clock ceiling for the whole harness run; it stops with the findings so far. |
| `consequentialTargets` | list of node ids | — | Delegations to these nodes pause for human approval; such a task always runs alone. |
| `maxDelegationDepth` | integer ≥ 0 | `2` | How deep harnesses may delegate to other harnesses (0 forbids it). Guards against self-referential loops. |
| `maxConcurrentTasks` | integer 1–8 | `3` | Parallel tasks when the planner marks them parallelizable (never the same node twice at once). |
| `maxTaskAttempts` | integer ≥ 0 | `0` | Retries of a failed task before it is recorded as failed (transient provider/tool errors). |
| `verification` | object | — | A reviewer node checks the findings before the run may report completion; a rejection feeds its feedback into a re-plan. |
| `verification.target` (required) | node id | — | Node id of the reviewer (not scheduled as ordinary work). |
| `verification.passSignal` (required) | string | — | Exact verdict the reviewer emits to pass (case-insensitive); anything else is a rejection. |
| `verification.maxAttempts` | integer ≥ 1 | — | Verification rounds (each costs a verifier call and a re-plan). |
| `verification.failClosed` | boolean | `false` | Reject completion when the verifier is missing/unavailable instead of accepting unverified. |
| `plannerLlm` | model (`llm` block) | — | Model for planning/re-planning; falls back to the node's `llm`, then DEFAULT_LLM. A model: `{ shortcut: <name from flows/model-shortcuts.yaml> }` or `{ provider, model, parameters? }` (provider = a PROVIDERS name or protocol). |
| `progressNarrator` | object | — | Phrases one status line from completed findings for the client. Sees only a sanitized summary, never reasoning or tool payloads; failures never affect the run. |
| `progressNarrator.enabled` | boolean | `true` | Defaults to true when the object is present. |
| `progressNarrator.llm` (required) | model (`llm` block) | — | Small fast model. A model: `{ shortcut: <name from flows/model-shortcuts.yaml> }` or `{ provider, model, parameters? }` (provider = a PROVIDERS name or protocol). |
| `progressNarrator.timeoutMs` | integer ≥ 1 | — | Deadline per narration call; a timeout just skips that status line. |
| `progressNarrator.maxOutputChars` | integer ≥ 80 | — | Ceiling on the status line. |
| `progressNarrator.includeHypotheses` | json | — | `{ active?, confirmed?, rejected? }` — which labelled hypotheses may be mentioned. |
| `carryForward` | one of `full`, `condensed` | `full` | `full` passes each worker's entire output to later rounds; `condensed` only its final answer — needed for long loops over large corpora. |
| `condensedFindingMaxChars` | integer ≥ 6000 | `6000` | Per-finding cap in `condensed` mode. |
| `resultMode` | one of `delegated`, `context` | `delegated` | `delegated`: keep the delegated answers (harness is the end node). `context`: one aggregated context message for a downstream synthesizer. |
| `streamDelegates` | boolean | `true` | Stream workers' tokens to the client. Set false when only a later synthesizer should be visible. |
| `stopSignal` | string | — | When a finding contains this text (case-insensitive) the loop stops as completed without another planner call. |
| `requiredFindingMarkers` | list of string | — | Line prefixes a worker result must contain to count as a finding. |
| `plannerless` | boolean | `false` | Skip all planner calls and loop the first allowlist target (or coverage-queue targets). |
| `maxStagnantIterations` | integer ≥ 1 | — | Plannerless: stop after this many passes without a new finding (stagnation-limit), keeping all findings. |
| `coverageQueue` | json | — | Deterministic plannerless document coverage: assigns documents to workers until the corpus is covered. See the flow schema for the full shape (targets per assignment mode must be allowlisted). Optional `summaryTriage` (staged only): `mode` llm (default, every summary via LLM triage), hybrid (a cross-encoder accepts the top `acceptTopK` share and excludes ranks beyond `excludeBelowRank` with a score below `excludeMaxScore`; only the gray zone goes to the LLM) or rerank. Shares are fractions of the scored collection; exclusions stay reopenable by global discovery. With a configured reranker, Stage-1 batches and the candidate freeze follow the rerank score (`rerankOrder: false` opts out). Any reranker failure falls back to full LLM triage in ledger order (fail-closed); an invalid block falls back to `mode: llm` with default thresholds and the trace diagnostic `summary_triage_config_invalid`. A `{{vars.*}}` placeholder in `summaryTriage` is resolved with the flow's declared default when the flow loads, so a per-request variable override does not change the triage mode; set it in the flow. |
| `coverageWorkerContextMaxChars` | integer ≥ 16000 | — | Max stable context passed to a coverage worker (besides its assignment). |
| `verificationContextMaxChars` | integer | — | Ceiling for the complete verifier state. |

**Example: Orchestrator with verifier**

```yaml
- id: orchestrator
  type: agent-harness
  llm: { shortcut: structured-pool }
  config:
    allowlist: [rag-context, betrieb-responder, retoure-responder]
    maxIterations: 6
    maxCost: 0.5
    carryForward: condensed
    resultMode: context
    streamDelegates: false
    verification: { target: agent-verifier, passSignal: "VERIFIKATION OK", maxAttempts: 2 }
```

**Notes**

- The verifier is referenced only via `verification.target`; the Studio draws that link dashed.
- `systemPrompt` steers the planner only. A plannerless harness (`config.plannerless: true`) never reads it — the wording of the actual work belongs on the `allowlist` nodes.

### `transform` — Transform

Deterministic lookup/regex rules that add fields to `classification`.

Runs no model. `derive` rules look up the value of a classification field in a static table and write the matched row's fields onto the classification (e.g. client → collection tags). `extract` rules apply a bounded regex to the user message (`from: query`) or a classification field and write a capture group to `target`. A non-match always writes an empty string, so the shape stays stable. At least one rule is required.

**When to use**

- Map a classifier value to technical parameters.
- Pull ids (ticket numbers) out of the message without an LLM.

**Node fields**

| Field | Use | Meaning for this type |
| --- | --- | --- |
| `llm` | ignored | Not used — the rules are deterministic, nothing is inferred. Use a `classifier` when you need a model. |
| `systemPrompt` | ignored | Not used — no model runs. |
| `tools` | ignored | Not used — MCP tools are called by `llm` and `tool` nodes. Route to one of those when this step needs a tool. |
| `label` | optional | Human-readable name shown on the canvas, in lists and as the default progress text. Purely cosmetic — edges, templates and references address the node by its `id`. |

**Settings (`config`)**

| Key | Type | Default | Description |
| --- | --- | --- | --- |
| `derive` | json | — | `[{ from, lookup: { <value>: { field: value } }, default? }]` (max 50). Without `default`, every field used anywhere in `lookup` is set to "" on a miss. Example: `[{"from":"client","lookup":{"mueller":{"clientTaiga":"mueller-gmbh"}},"default":{"clientTaiga":""}}]`. |
| `extract` | json | — | `[{ from: "query" \| <classification field>, pattern (≤200 chars), target, group? (default 1) }]` (max 20). Input is capped at 2000 characters. Example: `[{"from":"query","pattern":"#(\\d{2,6})","target":"ticketId"}]`. |

### `trigger` — Trigger

Declares how the flow starts without a chat request (webhook or schedule).

A pass-through at run time; its config registers the flow with the webhook endpoint (`POST /triggers/:flowId`, HMAC-signed) or the scheduler. The Triggers page lists and test-fires registered triggers.

**When to use**

- Flows started by external systems or on a schedule.

**Node fields**

| Field | Use | Meaning for this type |
| --- | --- | --- |
| `llm` | ignored | Not used — the node is a pass-through at run time. |
| `systemPrompt` | ignored | Not used. The message a trigger produces comes from `config.messageTemplate` / `config.scheduledMessage`. |
| `tools` | ignored | Not used — MCP tools are called by `llm` and `tool` nodes. Route to one of those when this step needs a tool. |
| `label` | optional | Human-readable name shown on the canvas, in lists and as the default progress text. Purely cosmetic — edges, templates and references address the node by its `id`. |

**Settings (`config`)**

| Key | Type | Default | Description |
| --- | --- | --- | --- |
| `mode` (required) | one of `webhook`, `schedule` | — | `webhook`: signed POST starts the flow. `schedule`: interval or cron. |
| `webhookSecret` | string | — | HMAC-SHA256 secret to verify webhook signatures. |
| `messageTemplate` | string (multi-line) | — | User message built from the webhook payload; supports `{{body.*}}`. |
| `synchronous` | boolean | `false` | Wait for the run and return its answer in the webhook response. |
| `intervalSeconds` | integer ≥ 60 | — | Fixed schedule interval (min 60). Mutually exclusive with `cron`. |
| `cron` | string | — | 5-field cron expression. Mutually exclusive with `intervalSeconds`. |
| `scheduledMessage` | string (multi-line) | — | Message for scheduled runs; supports `{{now.*}}`. |
| `tenantId` | string | — | Tenant context for scheduled runs. |
| `maxConcurrent` | integer 1–100 | `1` | Max simultaneous scheduled runs. |

**Example: Nightly**

```yaml
- id: nightly
  type: trigger
  config: { mode: schedule, cron: "0 3 * * *", scheduledMessage: "Tagesbericht {{now.date}}" }
```

### `assistant-context` — Assistant context

Loads a personal assistant's identity, skills, inbox and credentials.

Resolves the assistant for the request (from the request, a model name `assistant-<id>`, or `defaultAssistantId`) and injects its soul, skill index, peer inbox and credential state before the answering `llm` node. Fail-closed: without a complete (tenant, user, assistant) scope it passes the turn through with an explanatory message instead of borrowing another identity.

**When to use**

- First node of an assistant flow (paired with `assistant-learn` at the end).

**Node fields**

| Field | Use | Meaning for this type |
| --- | --- | --- |
| `systemPrompt` | ignored | Not used. The assistant's prompt sections are rendered from its own identity, skills and inbox — put flow-level wording on the answering `llm` node instead. |
| `llm` | ignored | Not used — this node loads context, it does not call a model. |
| `tools` | ignored | Not used. Which tools the assistant may use follows from its credentials and `config.requiresToolAuthority`. |
| `label` | optional | Human-readable name shown on the canvas, in lists and as the default progress text. Purely cosmetic — edges, templates and references address the node by its `id`. |

**Settings (`config`)**

| Key | Type | Default | Description |
| --- | --- | --- | --- |
| `defaultAssistantId` | string | — | Assistant used when the request names none (max 64 chars). |
| `maxContextChars` | integer 500–100000 | — | Budget for all assistant-owned prompt sections. |
| `requiresToolAuthority` | boolean | — | False for maintenance flows that must never act on a user's behalf. |

### `assistant-learn` — Assistant learn

Records the turn for the assistant and offers it to the learning pass.

Terminal node of an assistant flow: records what happened (depth, tools, aborts), settles skill canaries and offers the turn to the learning scheduler. Never fails the turn — the answer has already been delivered. Requires an `assistant-context` node earlier in the flow.

**When to use**

- Last node of an assistant flow.

**Node fields**

| Field | Use | Meaning for this type |
| --- | --- | --- |
| `llm` | ignored | Not used — the learning pass runs on the scheduler's own model, outside this node. |
| `systemPrompt` | ignored | Not used — no model is prompted here. |
| `tools` | ignored | Not used — MCP tools are called by `llm` and `tool` nodes. Route to one of those when this step needs a tool. |
| `label` | optional | Human-readable name shown on the canvas, in lists and as the default progress text. Purely cosmetic — edges, templates and references address the node by its `id`. |

**Settings (`config`)**

| Key | Type | Default | Description |
| --- | --- | --- | --- |
| `learn` | boolean | `true` | False for flows whose turns should be recorded but never learned from. |

## Edges and conditions

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | string | no | Optional edge id. |
| `source` | non-empty string | yes | Id of the node the edge leaves. |
| `target` | non-empty string | yes | Id of the node the edge enters. |
| `conditions` | string ≤ 1024 chars | no | Condition expression. Empty: the edge is always followed. The conditional edges leaving a node are checked in file order and the first that is true is taken; if none is, the run ends. |
| `label` | string | no | Display label in the Studio. |

A condition is an expression over the run state. It is evaluated by a safe evaluator — no code execution; anything outside the grammar is a validation error. The same grammar is used for `parallelNodes` conditions and the `whenClaim`/`whenParam` of overrides (there over claims and request parameters).

What a condition can read:

| Name | Group | Description |
| --- | --- | --- |
| `lastMessageText` | Run state | Text of the latest message. |
| `messageCount` | Run state | Number of messages so far. |
| `lastMessageType` | Run state | `human`, `ai`, `system` or `tool`. |
| `currentNodeId` | Run state | Node that just ran. |
| `toolResultCount` | Run state | Tool results collected so far. |
| `hasErrors` | Run state | Whether a node reported an error. |
| `errorCount` | Run state | Number of node errors. |
| `classLabel` | Classification | Value of the last classifier's `classKey` field. |
| `classification.<field>` | Classification | A field of the merged classification of this turn. |
| `node.<id>.classification.<field>` | Classification | A field as node `<id>` set it in this run (node ids with hyphens cannot be used here). |
| `turn[<n>].<id>.classification.<field>` | Classification | A field from node `<id>` n runs ago. |
| `role` | User & request | Caller's role. |
| `groups` | User & request | Caller's groups (list); use `groups.includes('x')`. |
| `plan` | User & request | Tenant plan. |
| `language` | User & request | Request language. |
| `userEmail` | User & request | Caller's email. |
| `clientId` | User & request | Calling client id. |
| `claims.<name>` | User & request | Any claim of the caller's token. |
| `params.<name>` | User & request | Any request parameter (metadata, conversation id, requested model, …). |

Operators and helpers (plus array index `x[0]`, numbers, `+ -`):

| Operator | Meaning |
| --- | --- |
| `==` | equal |
| `!=` | not equal |
| `>` | greater than |
| `>=` | greater or equal |

## Variables, constants and calculations

`variables` holds named values; a request can override them. Load-time references — variables, constants, allowlisted environment values and calculations — work in variable values and in any node or edge value. They are resolved when the flow loads and again per request when variables are overridden:

```yaml
variables:
  model_main: fast-pool
  max_tokens: "{{const.answer_max_tokens}}"
  max_tokens_draft: "{{= round(vars.max_tokens / 4) }}"
  region: "{{env.FLOW_PUBLIC_REGION}}"
```

| Reference | Description |
| --- | --- |
| `{{vars.<name>}}` | A flow variable. Variable values may reference each other (evaluated in dependency order; cycles are errors). Dotted names read into object values. An undeclared variable is a warning, since a request may supply it. |
| `{{const.<name>}}` | A global constant from `constants.yaml`. |
| `{{env.FLOW_PUBLIC_<NAME>}}` | An environment value whose name starts with `FLOW_PUBLIC_`; no other environment variable is readable. |
| `{{= <expression> }}` | A calculation over variables, constants and public env values. Inside it references are written without braces (`vars.x`, `const.y`, `env.FLOW_PUBLIC_Z`), strings in single quotes. Evaluated at load time, so it cannot read run-time values such as `context.*` or `classification.*`. |

Rules:

- A value that is exactly one placeholder keeps the referenced value's type (a number stays a number); inside longer text it is inserted as text.
- Cycles, unknown constants, environment variables outside `FLOW_PUBLIC_*`, and calculation errors are validation errors (`variables.<name>`, or the node/edge path). An undeclared `{{vars.*}}` in a node or edge is a warning.
- Variables supplied with a request are literals: they are never evaluated, but variables that reference them are.
- Runtime placeholders (`{{context.*}}`, `{{classification.*}}`, …) are left for the run; a calculation cannot read them.

Calculation operators:

| Operator | Meaning |
| --- | --- |
| `{{=  }}` | Start a calculation |
| `+` | Add numbers / join text (when either side is text) |
| `-` | Subtract |
| `*` | Multiply |
| `/` | Divide (division by zero is an error) |
| `%` | Remainder |
| `()` | Group |
| `==` | Equal |
| `!=` | Not equal |
| `<` | Less than (also <=) |
| `>` | Greater than (also >=) |
| `&&` | And |
| `\|\|` | Or |
| `!` | Not |
| `? '' : ''` | If a then b else c |
| `''` | Text literal |

Calculation functions:

| Function | Meaning |
| --- | --- |
| `round(x, digits)` | Rounds to `digits` decimals (default 0). |
| `min(a, b, …)` | Smallest number. |
| `max(a, b, …)` | Largest number. |
| `floor(x)` | Rounds down. |
| `ceil(x)` | Rounds up. |
| `abs(x)` | Absolute value. |
| `number(x)` | Text → number (error if not numeric). |
| `string(x)` | Value → text. |
| `upper(s)` | Upper case. |
| `lower(s)` | Lower case. |
| `trim(s)` | Strips leading and trailing spaces. |
| `length(x)` | Length of a text or list. |
| `concat(a, b, …)` | Joins values as text. |
| `coalesce(a, b, …)` | First value that is not null or empty. |
